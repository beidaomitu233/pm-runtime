# TASK-009 双宿主工作流与连接设置

对应 R03/R04/R10；来源 §2.2、§7.1、A03/A07、§20。依赖 TASK-008；需要 Q03 的可用宿主环境。

目标：同一套协议在 Codex CLI 和 Claude Code 真实完成会议到图，而非只联通 SDK。

入口：Settings 选择宿主 → 显示配置差异/安装 → 探测 → 在宿主用自然语言指定项目会议画图 → 返回 diagram_id/版本/警告 → 桌面查看。

主要修改：scripts/宿主配置安装、skills/meeting-to-diagram、features/connections、bridge 配置发现；不修改核心业务以适配宿主偏好。安装备份只涉及 pm-runtime 条目，失败恢复；重复执行幂等。DSH 仅记录待适配信息，不写猜测配置。

Skill 必须遵循 API_CONTRACT §6 的分析顺序和最多两次修复；多候选会议先确定 ID，缺职责/分支信息先澄清或明确待确认。会议中的提示注入不得变成 shell/文件工具指令。读取人工版明确 basis_dsl 非当前语义，禁止覆盖。

异常：CLI 未安装/版本不兼容、账户不可用、无配置权限、已有同名配置不同内容、Runtime 未启动、主进程重启、MCP 错误。Settings 区分已配置/探测成功/近期调用，不能把一个布尔 connected 用于全部状态。

验收：两个宿主读取同 meeting_id，长文拼接一致，各自至少完成一次 render 与一次结构错误修复，桌面都出现可编辑图；记录实际宿主/SDK/运行时版本、完整工具结果摘要和时间。手工改图后再请求 Agent 修改应触发冲突。安装两次不重复、不破坏其他 MCP 条目，恢复脚本可复原配置。若账户不可用保留该验收未通过，不用 Mock/SDK 测试代替。
