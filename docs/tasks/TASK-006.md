# TASK-006 生成横向与纵向泳道图

对应 R06；来源 §5.2、§11、A05 及图形质量要求。依赖 TASK-005。

目标：把职责和交接关系转成标准泳道容器、节点及可编辑跨泳道连线。

入口：宿主指定泳道维度和 orientation → render → Diagrams 打开。横向为流程向右/泳道上下排列，纵向为流程向下/泳道左右排列；选项不能只旋转文字或容器标题。

主要修改：diagram-engine/layout/swimlane、XML lane adapter、泳道 fixtures；复用 render 服务与持久化，不复制一套 API 或表。为 start/end 未指定 lane 的场景实现全局起止区。

规则：task/decision/subprocess 必须有合法 lane；职责信息不足使用待确认泳道或询问用户；混合维度 warning。lane 顺序取 DSL 数组顺序，ID 稳定；调整容器坐标后跨 lane 边必须重新路由，避免连接错位。使用现有 ELK 并补业务布局，不新建画布引擎。

异常：空泳道、重复 lane ID、未知 lane、循环回退、长中文标签、多条跨泳道边、同层节点拥挤。尺寸超上限明确失败，质量不足提示修正，不删除业务节点来美化图。

验收：3–6 个泳道、10–30 节点，包含至少两个 decision、回退与跨 lane 交接的 fixtures，在两种方向均可打开。100% 缩放无节点重叠/文字截断，主方向一致，起止区域合理，连线端点正确且分支标签可辨。`npm test -- swimlane` 验证节点位于对应容器、边引用正确；人工截图审查布局，不能只用 XML 单测证明可读性。
