# TASK-010 真实语料回归与 Windows 交付验收

对应 R01–R10；来源 §13、§15、§20。依赖 TASK-009 和 Q02/Q04。

目标：确认系统对真实会议有产品价值，并能在目标 Windows 环境安装、使用和重启恢复。

业务验收入口：安装 → 建项目 → 导入会议 → 两宿主生成 → 编辑保存 → 导出 → 退出重启 → 重开。验证 A01–A10 全链路，不重写已有业务模块。

主要修改：tests/corpus、回归脚本、验收记录、README、package:win 打包配置。人工样本由获准使用的至少 10 份真实/脱敏会议组成，覆盖单角色、跨职能、判断/回退三类；不能将生成的十个文本当真实语料。每份有人工参考流程，记录关键步骤遗漏、角色归属、分支与回退、出处可追溯、100% 可读性、是否需人工修正。

质量口径：不凭空承诺百分比阈值。按源文档逐份人工判定是否可用于沟通；明显遗漏关键步骤、错误职责或关键分支错误均未通过；修复后重新跑受影响案例。报告“初次生成”和“人工修改后”结果，不能混为模型一次生成能力。

可靠性：断网验证本地编辑/导出；强杀与重启检验已确认提交；磁盘满、损坏库、无效 DSL、非法 XML、重复请求、跨项目请求、两宿主并发、未保存退出均有结果。只日志脱敏摘要，不上传用户会议。

安装验收：固定 Windows x64 基线，安装包含 Node、WASM/布局所需资源（如有）、draw.io 和字体依赖，不依赖开发目录/PATH；标准用户可写数据目录，旧数据重装不覆盖；卸载默认保留用户资料并明确告知。证书/签名未准备时标注测试安装包，不伪称正式签名发布。自动更新与 macOS 打包不纳入。

完成证据：`npm ci`、`npm test`、`npm run build`、`npm run package:win` 实际结果；10 份人工评审记录、三格式产物、两个宿主联调、干净用户目录安装/重启记录、已知问题。Q01 删除范围最终签收、Q02/03/04 未完成时不得写“v0.1 全部通过”。
